Ваш BST из ЛР-1 — обёртка TreeIndex<TKey, TValue>, реализующая тот же интерфейс поиска Get(key) / ContainsKey(key) / Add(key, value). Внутри — Tree<Pair<TKey, int>> + Sequence<TValue> (индексы в дереве, значения — в массиве). Это ровно схема из пояснения 1.b методички.

ISortedSequence + бинарный поиск (M-2) — третья структура для сравнения. Массив + Add со сдвигом + IndexOf бинарным поиском.

Индексостроитель — класс PersonIndexer, который по коллекции Person и списку атрибутов строит map<string, IDictionary<string, ...>> (имя атрибута → индекс). Атрибуты: LastName, BirthYear, FullName, составной (LastName, BirthYear).

Замеры + CSV: std::chrono::high_resolution_clock, выгрузка в results.csv (структура, n, время построения, среднее время поиска, число коллизий).

Консольный UI: меню — генерация данных / ручной ввод / построить индексы / поиск по атрибуту / сравнить время / выгрузить CSV.

Тесты: Catch2 (или самописный assert-макрос) на:

IDictionary: пустая, одна запись, коллизии, перестройка вверх/вниз, удаление, итератор;

бинарный поиск: граничные индексы, отсутствующий элемент;

BST-индекс: сравнение с эталонным std::map;

PersonIndexer: корректность индексов на малых данных.

Обоснование выбора хеш-таблицы как основной структуры (для ТЗ — дословно)
Обоснование выбора структуры данных.

Задача индексирования (И-5) сводится к многократному точечному поиску объектов по значению атрибута: Get(key), ContainsKey(key). Упорядоченный обход и диапазонные запросы в базовой постановке не требуются (range-поиск — отдельная модификация И-5.1, которая не выбрана). Отсюда критерий выбора — средняя сложность точечного поиска при разумной сложности реализации.

Сложность поиска. Хеш-таблица — O(1) в среднем; сбалансированное BST — O(log n); бинарный поиск по сортированному массиву — O(log n). При n = 10⁴–10⁵ разница измерима (см. раздел «Результаты замеров»).

Сложность построения. Хеш-таблица — O(n) амортизированно (с учётом перестроек при n = c); BST из произвольной последовательности — O(n log n) в среднем и O(n²) в худшем без балансировки; сортированный массив со вставкой — O(n²) из-за сдвигов. Для индекса, который строится один раз, а используется многократно, это приемлемо, но хеш-таблица выигрывает и здесь.

Отсутствие требования упорядоченности. Преимущество BST (упорядоченный обход, range-запросы) в базовой И-5 не востребовано. Платить логарифмическим поиском за неиспользуемую функциональность нерационально.

Простота и контролируемость. IDictionary на массиве с хеш-функцией и цепочками (M-5.1) проще в отладке, чем балансировка BST или B-дерева; граничные случаи (пустая таблица, коллизия, перестройка) легко покрываются тестами.

Расширяемость и сравнимость. Модификация M-5.2 (открытая адресация) реализуется в том же классе заменой стратегии разрешения коллизий — это даёт вторую точку сравнения и закрывает требование ЛР о сравнении алгоритмов.

Вывод. Для точечного индексирования хеш-таблица оптимальна по критерию «средняя сложность поиска / сложность реализации». BST из ЛР-1 сохранён в проекте как эталон сравнения (структура с O(log n) и упорядоченным обходом) и как демонстрация альтернативного подхода.
